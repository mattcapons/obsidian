-3-          Order Statistics
Input: A set of n (distinct) numbers and an integer i, with 1≤ i ≤ n
Output: The element with rank i x  A that is larger than exactly i-1
other elements of A

      • i = 1: minimum;
      • i = n: maximum;
      • i = (n+1)/2 or (n+1)/2: lower or upper median.
      Naive algorithm: Sort and index i th element.

      Worst-case running time = (n lg n) + (1)
                               = (n lg n),
      using merge sort or heapsort (not quicksort).

-8-     Selection in linear time

      Select the i th smallest of n elements (the element with rank i).
      Two versions:
      • Randomized divide-and-conquer algorithm (linear in
        average)
      • Deterministic version (derandomization – linear in the
        worst case)
-9-         Randomized divide-and-
            conquer algorithm
      RAND-SELECT(A, p, q, i) ⊳ i th smallest of A[ p . . q]
        if p = q then return A[ p]
        r  RAND-PARTITION(A, p, q)
        kr–p+1                 ⊳ k = rank(A[r])
        if i = k then return A[ r]
        if i < k
           then return RAND-SELECT( A, p, r – 1, i )
           else return RAND-SELECT( A, r + 1, q, i – k )

- 24 -        Summary of randomized order-
              statistic selection
           • Works fast: linear expected time.
           • Excellent algorithm in practice.
           • But, the worst case is very bad: (n2).
         Q. Is there an algorithm that runs in linear
            time in the worst case?

            Tarjan [1973].

- 36 -           Conclusions
         • Since the work at each level of recursion is a
           constant fraction (19/20) smaller, the work
           per level is a geometric series dominated by
           the linear work at the root.
         • In practice, this algorithm runs slowly,
           because the constant in front of n is large.
         • The randomized algorithm is far more
           practical.
